Executive Decision

Do not treat the current payment stack as production ready. The highest-risk issues allow underpayment-to-credit escalation, subscription plan escalation, unauthenticated credit use, client-side mutation of billing tables, duplicate webhook credit grants, silent webhook drops, and potential Google Play payments policy non-compliance for Android distribution.

End-to-End Flow Observed

Pricing UI components/PricingContent.tsx loads plans and packs from Supabase.
Order API api/create-order.ts or api/create-subscription.ts creates Razorpay objects.
Checkout JS services/razorpayService.ts loads Razorpay checkout in the browser/WebView.
Verify API api/verify-payment.ts checks HMAC and calls Supabase RPC.
Credits verify_razorpay_payment grants credits/subscription benefits in Supabase.

Local Runtime Finding

  • Local preview warned: Supabase credentials missing, app running in offline mode.
  • Built local web and Android assets contained VITE_RAZORPAY_KEY_ID as undefined because env vars were absent at build time.
  • This must be guarded in CI and release builds.
