Manual Production Readiness Checklist

Razorpay

  • Dashboard plans match server DB active plans.
  • Webhook URL points to production endpoint and uses rotated secret.
  • Test webhook delivery succeeds and duplicate delivery is safe.
  • Capture/payment status is reconciled before credit grant.
  • Refund and chargeback handling is documented and tested.

Supabase

  • Billing write policies removed from client roles.
  • Service role key only exists server-side.
  • RPCs use fixed search path and explicit validation.
  • Ledger and idempotency constraints exist.
  • Backups and recovery path are confirmed before migration.

Frontend

  • Pricing UI handles loading, empty config, errors, payment success, duplicate callback, and cancel states.
  • Client sends product IDs only, never trusted prices or grant details.
  • Checkout brand, support email, policy links, and receipt copy are consistent.
  • Android and web route payment methods based on policy-safe platform capability.

Release

  • TypeScript, lint, tests, secret scan, web build, Android build, and Android lint pass.
  • Environment validation passes for preview and production.
  • Support runbook exists for failed payment, duplicate charge, missing credits, cancellation, and refund.
  • Monitoring alerts are configured for webhook failures and unusual credit grants.
