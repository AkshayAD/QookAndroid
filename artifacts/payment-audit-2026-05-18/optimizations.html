Security and Fraud Optimization

Opportunity Benefit Implementation Notes
Payment intent expiry and single-use state Prevents stale or reused checkout results from granting benefits later. Set short expiry on pending intents. Move states through created, paid, granted, expired, refunded.
Provider fetch before grant Reduces trust in client callback payloads and catches partial/cancelled payments. Fetch Razorpay payment/order/subscription during verification and compare amount, currency, status, and linked IDs.
Fraud velocity checks Flags abuse patterns such as repeated low-value orders, verify attempts, and failed webhook signatures. Track attempts by user, IP, device fingerprint, product, and provider object ID.
Admin-only entitlement correction workflow Prevents manual support fixes from becoming untracked data edits. Corrections should require reason, actor, before/after, source ticket, and immutable audit event.
Replay protection for checkout callback Keeps browser callback retries from generating inconsistent UI or duplicate records. Use server idempotency keys and return the canonical final payment state to the client.
Strict environment separation Prevents test keys, live keys, preview builds, and production DB from mixing. Validate key prefixes and deployment environment. Block rzp_test_ in production and live keys outside production.

Reliability and Reconciliation

Opportunity Benefit Implementation Notes
Daily provider reconciliation job Catches missed webhooks, failed grants, refunds, cancellations, and subscription renewals. Compare Razorpay/Play provider records with local ledger by day and subscription cycle. Produce actionable discrepancy rows.
Webhook replay tool Speeds up safe recovery from transient DB or deploy failures. Replay only stored verified raw events or provider-fetched events. Make replay idempotent and auditable.
Payment state machine Makes edge cases explicit and prevents impossible status transitions. Define allowed transitions for order, subscription, credit grant, refund, chargeback, and cancellation states.
Provider outage mode Improves user experience when Razorpay or Play Billing is degraded. Show a payment-unavailable state and avoid creating partial local intents when provider calls fail.
Structured correlation IDs Allows support and engineering to trace one payment across browser, API, DB, webhook, and provider. Log intent ID, provider order ID, provider payment ID, subscription ID, user ID hash, and request ID.

User Experience and Conversion

Opportunity Benefit Implementation Notes
Unified pricing component Reduces pricing drift and user confusion. Replace duplicate pricing surfaces with one component backed by one normalized view model.
Server-backed checkout preview Shows exactly what the server will charge before opening checkout. Display product, amount, discount, renewal amount, taxes if any, and credit grant based on server intent response.
Clear success and pending states Prevents repeated payment clicks when confirmation is delayed. After checkout callback, show verifying, granted, pending webhook, failed, or support-needed states from server status.
Cancellation clarity Reduces support tickets and charge disputes. Show current period end, renewal disabled state, access-through date, and reactivation path.
Receipt and support links Helps users self-serve payment questions. Add receipt/invoice link, payment ID, plan name, and support contact after successful payment.
Localized payment copy Improves trust for Indian payment methods and first-month offers. Use consistent Rs pricing, renewal language, GST/tax copy if applicable, and provider method availability.
Android-specific payment messaging Avoids showing web-only Razorpay copy in Play Billing builds. Render payment provider, cancellation, and support copy based on platform and distribution channel.

Performance and Frontend Quality

Checkout Load

  • Lazy-load Razorpay only when the user initiates payment, which is already the current direction.
  • Add timeout and retry messaging around checkout SDK load failure.
  • Prefetch pricing data after login but avoid blocking the main dashboard on payment config.

Bundle and UI

  • Remove duplicate pricing page implementation after choosing the canonical component.
  • Keep payment route chunks isolated from core meal-planning route chunks.
  • Add resilient empty/error states when plan or pack rows are missing.

Database and Query Optimization

Area Optimization Reason
Indexes Add or verify indexes on user_id, provider payment/order/subscription IDs, event IDs, active status, and created timestamps. Payment support, reconciliation, and webhook processing depend on quick lookups.
Constraints Add unique constraints for provider event ID, payment ID, order ID, and credit grant idempotency key. Database should enforce duplicate prevention even if application code has a bug.
RPCs Use transaction-safe RPCs for grant and consume operations. Centralizes credit accounting and prevents race conditions.
Archiving Partition or archive old webhook payloads and usage rows if volume grows. Keeps operational tables responsive without losing audit history.
